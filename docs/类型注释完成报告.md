### 2. 采用的安全策略

#### ✅ 正确做法
1. **只优化函数体内部的局部变量**
   ```cython
   def some_method(self, value):
       cdef int i, n
       cdef double result
       # 使用类型化的局部变量
   ```

2. **循环索引和计数器明确为 `int`**
   ```cython
   cdef int i, j, n = len(data)
   for i in range(n):
       ...
   ```

3. **数值计算中间变量明确为 `double`/`float`**
   ```cython
   cdef double price, commission, total
   ```

4. **使用 memoryviews 和 nogil 优化性能关键循环**
   ```cython
   cdef double[:] src = self.data.array
   cdef double[:] dst = self.line.array
   with nogil:
       for i in range(start, end):
           dst[i] = compute(src[i])
   ```

#### ❌ 避免的做法
1. **不修改可能接收 `None` 的公共API参数类型**
2. **不强制转换可能为 `None` 的默认参数**
3. **不在构造函数中对可选参数强制类型**

### 3. 失败案例与教训

#### 问题1: 强制函数签名参数类型导致测试失败
**错误做法**:
```cython
def __init__(self, dt=None, int size=0, double price=0.0):
    ...
```

**问题**: 当调用端传入 `None` 时，Cython 无法将 `None` 转换为 `double/int`，抛出 `TypeError: must be real number, not NoneType`

**解决方案**: 保持签名动态，只在函数体内部做类型转换
```cython
def __init__(self, dt=None, size=0, price=0.0):
    cdef int size_val = size if size is not None else 0
    cdef double price_val = price if price is not None else 0.0
    ...
```

#### 问题2: 布尔参数强制类型化
**错误做法**:
```cython
def method(self, bint flag=True):
    ...
```

**解决方案**: 保持参数动态，在函数内部转换
```cython
def method(self, flag=True):
    cdef bint flag_val = bool(flag)
    ...
```

## 性能优化技术总结

### 使用的Cython优化技术

1. **类型声明 (Type Declarations)**
   ```cython
   cdef int i, n
   cdef double price, value
   cdef object data, broker
   ```

2. **Typed Memoryviews**
   ```cython
   cdef double[:] src_mv = self.data.array
   cdef double[:] dst_mv = self.line.array
   ```

3. **GIL释放 (nogil)**
   ```cython
   with nogil:
       for i in range(start, end):
           # C-level computation without Python overhead
   ```

4. **编译器指令**
   ```cython
   # cython: boundscheck=False
   # cython: wraparound=False
   # cython: cdivision=True
   # cython: nonecheck=False
   ```

5. **装饰器优化**
   ```cython
   @cython.final
   @cython.cdivision(True)
   def method(self):
       ...
   ```
