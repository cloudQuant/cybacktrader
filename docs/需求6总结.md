## 关键决策

### 采用保守方案B

**方案：** 创建内部cdef辅助函数，不直接修改公开API

**理由：**
1. **零API破坏风险** - 保持100%兼容性
2. **仍有性能收益** - 即使在非主要瓶颈上也有1.29x提升
3. **可扩展性好** - 验证后可应用到更多文件
4. **风险完全可控** - 测试全部通过

### 为什么不采用激进方案

**弃用方案A：** 直接将def改为cpdef

**原因：**
1. 可能破坏子类重写
2. 可能破坏鸭子类型
3. 可能影响动态调用
4. 与项目的"100% API兼容"要求冲突

## 技术亮点

### cdef辅助函数的优势

```cython
# 原始：60行Python逻辑
def update(self, size, price, dt=None):
    # 大量if-elif-else...
    return self.size, self.price, opened, closed

# 优化：调用C级辅助函数
def update(self, size, price, dt=None):
    _calc_position_delta(...)  # C级调用
    return self.size, self.price, opened, closed
```

**性能优势来源：**
1. 消除了Python对象装箱/拆箱
2. 减少了解释器开销
3. 编译器可进行更激进的优化
4. 可以释放GIL实现并行
