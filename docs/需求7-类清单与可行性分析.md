## 关键发现

### 1. 项目架构不适合cdef class

backtrader的设计理念：
- **灵活性优先**：大量使用元类、动态类生成
- **Python友好**：用户可以轻松扩展和定制
- **鸭子类型**：依赖动态特性

**与cdef class的理念冲突！**

### 2. 热路径不在类定义上

性能瓶颈在：
- **数组访问**（已在需求5优化）
- **循环计算**（已在需求5/6优化）
- **函数调用**（已在需求6优化）

而不在：
- 类的实例化
- 属性访问（如果已经有类型注释）

### 3. 边际收益递减

```
需求5（类型注释）：5-10x提升 ⭐⭐⭐⭐⭐
需求6（cdef函数）：额外3-7%  ⭐⭐⭐⭐☆
需求7（cdef class）：额外<1%  ⭐☆☆☆☆
```

**进一步优化的收益越来越小，但风险却越来越大！**
