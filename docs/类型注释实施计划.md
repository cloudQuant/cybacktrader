# cybacktrader 类型注释实施计划

## 项目概况
- 总计 **63** 个 `.pyx` 文件需要分析和优化
- 目标：为明确类型的参数和局部变量添加 Cython 类型注释，提升性能

## 安全策略（基于前期失败经验）

### ✅ 可以做的
1. **函数体内部局部变量**使用 `cdef` 声明类型
   ```cython
   def some_method(self, value):
       cdef int i, n
       cdef double result
       # 使用类型化的局部变量
   ```

2. **循环索引和计数器**明确为 `int`
   ```cython
   cdef int i, j, n = len(data)
   for i in range(n):
       ...
   ```

3. **数值计算中间变量**明确为 `double`/`float`
   ```cython
   cdef double price, commission, total
   ```

4. **内部私有方法**如果确定参数类型且不接收 `None`，可以添加类型
   ```cython
   cdef inline double _calculate(self, double value, int count):
       ...
   ```

5. **属性访问优化**：缓存对象引用减少重复查找
   ```cython
   cdef object lines = self.lines
   cdef object broker = self.broker
   ```

### ❌ 不能做的
1. **不要修改公共API函数签名的参数类型**，特别是：
   - 可能接收 `None` 的参数（如 `dt=None`, `size=0`, `price=0.0`）
   - 可能接收多种类型的参数（如 `data` 可能是对象、整数或字符串）
   - 布尔标志参数（如 `notify=True`），除非确定只接收布尔值

2. **不要强制转换可能为 `None` 的返回值**

3. **不要在构造函数 `__init__` 中对默认值参数强制类型**

## 每个文件的检查清单

对于每个文件，按以下顺序检查：

1. ✅ **识别循环**：所有 `for` 循环的索引变量用 `cdef int`
2. ✅ **数值计算**：中间变量用 `cdef double`
3. ✅ **对象引用缓存**：频繁访问的属性先缓存到 `cdef object`
4. ✅ **内部辅助方法**：如果确定类型且为私有，可以用 `cdef` 定义
5. ⚠️ **公共方法参数**：保持动态类型，不修改签名
6. ✅ **添加 @cython 装饰器**：适当使用 `@cython.boundscheck(False)`, `@cython.wraparound(False)` 等

## 测试验证流程

```bash
# 3. 如果失败，分析错误
#    - 如果是 TypeError: must be real number, not NoneType

#    
#    - 如果是其他错误，具体分析调整
```
