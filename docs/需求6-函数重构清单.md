# 需求6：函数重构为Cython函数清单

## 核心原则

根据Cython文档：
- **def** - Python函数，可从外部调用，性能最慢
- **cdef** - C函数，仅内部调用，性能最快，不能被Python代码或子类访问
- **cpdef** - 混合函数，可从任何地方调用，从Cython调用时使用C约定，有微小开销

### 4. **不应重构的方法**

以下方法应保持`def`：
- 所有`__init__()`构造函数（除非不需要外部实例化）
- 所有`__str__()`、`__repr__()`等魔术方法（除性能关键的）
- 所有需要被Python代码直接调用的公共API
- 所有可能被子类重写的虚方法（除非使用@cython.final标记）
- 包含复杂Python对象操作的方法

## 重构原则

### 安全规则
1. **保持API兼容性**：公开方法使用`cpdef`，内部方法使用`cdef`
2. **类型安全**：只对明确类型的参数添加类型声明
3. **None处理**：可能接收None的参数不强制类型化
4. **渐进式重构**：一次重构一个文件，立即测试
5. **使用@cython.final**：对不需要重写的方法添加此装饰器

### 性能优化
1. **内联候选**：简单的getter/setter/布尔判断 → `cdef inline`
2. **返回类型声明**：所有cdef/cpdef函数声明返回类型
3. **参数类型声明**：对数值型参数使用C类型（int, long, double, bint）
4. **GIL释放**：纯数值计算使用`nogil`

### 测试策略
1. 重构一个文件后立即编译：`python setup.py build_ext --inplace`
2. 运行完整测试套件：`pytest tests -n 8`
3. 如果失败，分析错误并回滚或修复
4. 验证性能基准：确保没有性能退化

## 执行顺序

1. **第一批**：linebuffer.pyx（核心数据结构）
2. **第二批**：position.pyx, trade.pyx（交易核心）

## 预期收益

- **性能提升**：5-15%额外性能提升（在需求5的基础上）
- **类型安全**：编译时类型检查，减少运行时错误
- **内存优化**：C函数调用开销更小
- **互操作性**：cpdef函数可以从Cython和Python高效调用
